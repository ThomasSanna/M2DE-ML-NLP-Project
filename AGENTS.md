# AGENTS.md

Rules for AI agents. Each one prevents a specific breakage. User docs: `README.md`, `doc/api_doc.md`.

PoC of a GLPI support chatbot. Active work is the API in `api/` (memory, answer engine, GLPI
worker): FastAPI, SQLAlchemy async, Alembic, pgvector, Python 3.12, `uv`. Embeddings, reranker
and LLM (vLLM) are remote servers behind the university VPN; web search is Exa. Guardrails are
not implemented: do not build them unless asked.

## Commands

Run from `api/` (Settings reads `../.env`). `scripts/*.sh` are bash (Git Bash on Windows).

```bash
uv run ruff format . && uv run ruff check .
uv run pytest -x -q                       # Docker required
uv run alembic revision --autogenerate --rev-id 0005 -m "..."   # sequential ids
uv run alembic check                      # must print "No new upgrade operations"
```

From the repo root, `docker compose up -d --build api` after any change under `api/` (the image
does not mount the source).

## Definition of done

1. `ruff format` + `ruff check`: zero findings, no new `noqa`.
2. `pytest -x -q` passes, with a test covering the behavior change.
3. `alembic check` if `app/models/` changed.
4. Docs updated (see Docs).

If Docker or the VPN is unavailable, say which step was not run.

## Never

- `docker compose down -v`, `docker volume rm`, `DROP`/`TRUNCATE` on the dev DB: no backup.
- Read or print `.env` values, or commit any real credential.
- Edit an applied migration: add a new revision.
- Weaken auth: `require_api_key` (constant-time) on the API routes, GLPI HMAC on
  `/api/v1/ingest/*`. No timestamp window on the HMAC: GLPI replays queued webhooks later.
- Call the real model servers or Exa from tests; add a local model container or torch.
- Add AI attribution to commits or PRs.

## Ask first

- A new dependency (`uv add`; Docker builds with `--locked`).
- Changes in `glpi/`, `ldap/`, `scripts/configure-glpi.sh`: shared with the other project member.
- Running `scripts/load_knowledge.py`: not idempotent, duplicates every row.
- Changing `EMBEDDING_MODEL`, `EMBEDDING_DIM` or `embedding_instruction`: every stored vector
  must be re-embedded.

## Architecture rules

- Settings, DB and remote clients come only through `SettingsDep`, `SessionDep`, `EmbedderDep`,
  `RerankerDep`, `ChatModelDep`, `WebSearchDep`. Never `get_settings()` or a new client in a
  route or service: it bypasses the test fakes.
- Logic lives in `app/services/`. Services own `commit()`; routes never commit, except
  `routes/ingest.py`. Response model via the return annotation.
- A new setting goes in `app/core/config.py`, `.env.example`, the `x-api-env` anchor of
  `docker-compose.yml` (the container gets only those) and `doc/api_doc.md`. Secrets are
  `SecretStr`; optional ones `X | None = None`, listed in `_empty_as_none`.
- Remote clients raise their domain error (`EmbeddingError`, `RerankerError`, `LLMError` →
  generic `502`; never return the cause). `WebSearchError` is fed back to the agent instead.

## Invariants that are easy to break

- **Vectors**: `halfvec(3584)` with HNSW; never `Vector` (HNSW caps it at 2000 dims). Embed the
  question only, with the same instruction prefix on stored questions and queries.
- **Search**: keep `.order_by(cosine_distance).limit(k)` on the raw expression, or the HNSW
  index is skipped. Filter `status == ACTIVE`.
- **Webhook**: verify the HMAC on the raw `request.body()` before parsing. The handler only
  stores the event and returns `202`; `services/glpi_worker.py` does the work.
- **Worker**: commits `processing` before answering and never replays it (a duplicate public
  followup is emailed). `_awaits_bot` must keep skipping the bot's own followups, or it answers
  itself in a loop. A handed-over ticket (`ticket_answer.escalated`) is never answered again.
- **Answer engine**: commit right after retrieval (the agent loop must not hold a connection).
  Agent messages are append-only (prompt cache). Only refs shown to the model may be cited.
  The thread and handover reason are logged at DEBUG only.
- **Enums**: `str_enum()` (VARCHAR + CHECK), never a native `ENUM`. Autogenerate misses CHECK
  changes: write `drop_constraint` / `create_check_constraint` by hand.
- **Migrations**: read every autogenerated one (it misses CHECKs, renames, server defaults);
  remove the unused `pgvector.sqlalchemy` import.

## Tests (`api/tests/`)

- Real throwaway pgvector container migrated with Alembic; no SQLite, no DB mocks.
- Fixtures: `client` (fake embedder, reranker, scripted LLM, no web search), `auth`,
  `settings`. Settings are built with `_env_file=None`.
- Synchronous only (`TestClient`, `asyncio.run`); no pytest-asyncio.
- `client` truncates the tables after each test: add any new table to that statement.
- `FakeEmbedder` is a bag of words: similar texts must share words.
- New route: success, `401`, `422`, and `502` per remote model.

## Docs

A route, schema, status code, table or setting change updates, in the same commit,
`doc/api_doc.md`, the route table in `README.md` and `.env.example`. The `README.md` model
table is the source of truth for model names.

## Git

Feature branch, PR to `dev`; `main` only through a PR, never pushed directly. Conventional
Commits in English, one logical change per commit, files staged by explicit path (the tree
often holds unrelated changes, e.g. `metrics/*.csv`).
